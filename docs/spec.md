# 仮想ネットワーク上の複数クライアント・アクセス再現ツール 仕様書

本ツールは、仮想ネットワーク（Dockerブリッジネットワーク）上で、それぞれ異なるIPアドレスとデバイス特性（User-Agent等）を持った複数のクライアントからのHTTP/HTTPSアクセスをシミュレートし、サーバーへの負荷や動作を検証するための負荷テストツールです。

## システム構成・ディレクトリ構造

```text
/home/d-ogaw25/workspaces/network-client-simulator/
├── config.yaml          # テストシナリオやターゲットの設定
├── docker-compose.yml   # クライアントコンテナおよび検証サーバーの定義
├── Makefile             # ビルド・実行・集計の統合コマンド
├── docs/
│   └── spec.md          # 本仕様書（本書）
├── client/              # クライアントシミュレータ (Go)
│   ├── main.go
│   └── device.go        # デバイスプロファイル（User-Agent等）の定義
├── server/              # 動作確認用のモックサーバー (Go)
│   └── main.go          # 送信元IPとヘッダーをロギングする検証用Webサーバー
└── manager/             # 各クライアントの結果を集計するマネージャーツール (Go)
    └── main.go
```

## 各コンポーネント詳細

### 1. 設定ファイル (`config.yaml`)
テストの全体的なパラメータと、クライアントが実行するシナリオ（リクエストシーケンス）を定義します。

* **パラメータ**:
  * `target_url`: テスト対象サーバー of ベースURL (DNS・ドメイン設定を使用しない場合のフォールバック)
  * `dns_server`: 実験用DNSサーバーのIPとポート番号 (例: `192.168.10.53:53`)
  * `target_domain`: ターゲットWebサーバーのドメイン名 (例: `www.v6d.dsm.cis.kit.jp`)
  * `target_port`: ターゲットWebサーバーの待受ポート (例: `80`)
  * `device_profile`: プロセス全体で一貫して固定するデバイスプロファイル名 (任意)
  * `duration_seconds`: テスト全体の継続時間（秒）
  * `vus_per_client`: クライアントコンテナあたりの同時仮想ユーザー数 (VU)
  * `think_time_ms`: デフォルトのステップ間の思考時間（ミリ秒）
  * `scenario`: 実行するリクエストステップのリスト（パス、メソッド、ボディ、思考時間など）

### 2. クライアントシミュレータ (`client/`)
* **デバイスプロファイル (`device.go`)**:
  * iPhone, iPad, Android, Windows, Mac, Linux などの OS と各ブラウザ（Safari, Chrome, Firefox, Edge）を組み合わせた 12 種類の代表的なデバイスの User-Agent とヘッダーの組み合わせ（プロファイル）を定義。プロセス（コンテナ全体）の開始時に1つ選ばれて固定され、全VUに一貫して適用されます（`config.yaml` で直接指定することも可能）。
* **シミュレータ本体 (`main.go`)**:
  * `config.yaml` を読み込み、指定された `vus_per_client` 分のゴルーチンを起動します。
  * 各ゴルーチンは独立した HTTP クライアント（Cookie Jarを保持し、セッションを維持）として、シナリオに沿ってリクエストを繰り返し送信します。
  * **明示的DNS・ブラウザ偽装機能**: `dns_server` と `target_domain` が指定された場合、標準のDNS解決に依存せず、プログラム内部で直接DNS AAAA解決を実行して一時IPv6を取得。そのIP宛てにTCP接続を張りますが、HTTPの `Host` ヘッダーは元のドメイン名に維持し、かつ `DisableKeepAlives: true` によって接続ごとのDNS解決を強制します。
  * **高負荷対策（DNSリトライと起動遅延）**: 多数のコンテナ起動時にDNSサーバー過負荷やパケットロスによる名前解決失敗が発生するのを防ぐため、DNS解決に「指数バックオフとランダムジッターを伴うリトライ（最大3回）」を組み込み、かつ仮想ユーザーの実行開始直後に `0〜2000ms` のランダムな待機時間（起動ディレイ）を挿入して負荷を平滑化しています。
  * 各リクエストの実行結果（開始時刻、レイテンシ、ステータスコード、エラー内容、使用された `user_agent` 文字列）およびコンテナ全体の `device_profile` メタデータを記録し、終了時に `/results/client-<hostname>.json` という共有ボリューム上のファイルに保存します。

### 3. マネージャーツール (`manager/`)
* テスト終了後、共有ディレクトリ内の全JSONファイルを読み込みます。
* 以下のメトリクスを集計し、見やすく色付けされたコンソールレポートを出力します。
  * 総リクエスト数、成功数、失敗数
  * 平均、最小、最大、90%/95%/99% パーセンタイルのレイテンシ
  * HTTPステータスコードの分布
  * エラーの概要（接続タイムアウトや特定のエラーレスポンスなど）

### 4. 検証用モックサーバー (`server/`)
* リクエストを受信すると、送信元のリモートIP（Dockerネットワーク上のコンテナIP）と `User-Agent` を抽出し、見やすくコンソールにログ出力するシンプルな Web サーバーです。
* クライアントがシナリオに沿って正しく状態を維持できているかを検証するため、シンプルなログインセッション（Cookieの検証）機能も実装します。

### 5. 実行環境の定義と環境変数によるカスタマイズ
* **Docker Compose (`docker-compose.yml`)**:
  * `server`: 検証用モックサーバーのコンテナ（※ローカル検証用。ホストネットワークモード稼働時は無効）
  * `client`: クライアントシミュレータのコンテナ。IPv6対応の Docker ブリッジネットワーク（`sim-net`）に所属し、`--scale client=N` による複数コンテナのスケールアウトに対応。コンテナは IPv4/IPv6 デュアルスタックで構成され、外部の IPv6 実験環境宛てに通信する際は、ホストPC側での IPv6 転送有効化（sysctl）と ip6tables によるマスカレード（NAT66）の設定が必要です。
  * `results-volume`: クライアントの結果ファイルを manager と共有するためのバインドマウント
* **`Makefile`**:
  * `make build`: Goバイナリのビルド
  * `make run-test`: サーバー起動、クライアント実行、終了待機を行います。
    * **クライアント数の変更**: `make run-test CLIENT_COUNT=5` のように引数でコンテナ数を上書きできます（デフォルト: 3）。
    * **アクセス先サーバーの変更**: 環境変数 `TARGET_URL` でアクセス先URLを上書きできます（例: `TARGET_URL=https://example.com make run-test`）。
  * `make report`: マネージャーツールを起動し、結果を集計して表示
  * `make clean`: テスト結果の一時ファイルやコンテナの削除
